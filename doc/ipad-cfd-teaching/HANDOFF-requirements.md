## 2. 需求规格草案（已完整呈现给用户，待确认）

### 2.1 愿景
iPad 上的教学型 CFD App，定位 OpenFOAM 的「引桥课」：零环境成本走通「从输入到流场」闭环，对照真实 OpenFOAM 源码建立心智模型。边界：不替代 OpenFOAM，只解决上手第一公里；核心差异化 = 源码入门（看懂 OpenFOAM 的 C++）。

### 2.2 目标用户
CFD/OpenFOAM 初学者（学生、自学者、课堂场景）：被环境配置与概念门槛劝退、有 iPad、想低成本入门。

### 2.3 功能需求
- FR1 运行：端上求解 CFD 算例出流场（首案例 = 2D 顶盖驱动方腔）。
- FR2 编辑:图形/表单编辑算例输入（边界条件、参数），可见等价 OpenFOAM 字典文本。
- FR3 可视化：速度矢量/流线、压力云图、残差曲线、随时间演化。
- FR4 源码入门：点概念/函数 → 真实 OpenFOAM C++ 源码 + 解释 + 数学公式。
- FR5 交互式理解：单步/播放求解；点网格单元看数值与离散细节。

### 2.4 非功能需求
- NFR1 零环境成本（App Store 一键装）。NFR2 防挫败（预置稳定参数必出结果）。
- NFR3 触屏友好（无键盘完成全部输入）。NFR4 交互性能（实时观看、随时单步）。
- NFR5 离线可用（教学内容内嵌）。

### 2.5 约束
- C1 App Store 2.5.2：不能在设备上编译用户代码 → 求解器须预编译内置。
- C2 OpenFOAM 本体依赖 MPI/wmake → 不可整搬，引擎须重新实现。
- C3 OpenFOAM 为 GPL v3，与 App Store 分发冲突 → 内嵌源码片段有法律风险。
- C4 CFD 数值会发散 → 须锁定安全参数范围。

### 2.6 范围（MVP）
做：单案例（icoFoam + 2D cavity）做到极致；4 种边界条件（fixedValue/noSlip/zeroGradient/empty）；2D 均匀网格。
不做：3D、湍流、网格生成、多求解器、用户自定义案例。
演进：加新案例 = 加数据不改框架。

## 3. 等待用户回答的 3 个确认问题

1. 「源码入门是核心差异化」还认吗？（它是最贵的需求：FR4、一半架构复杂度、GPL 风险全因它；砍掉则难度减半但沦为普通演示 App。）
2. FR1–FR5 有无增删？特别提醒考虑两个未提的候选：保存/分享结果；内置教程关卡（引导式课程 vs 自由探索）。
3. 「课堂场景」是认真的还是顺带？（认真 → 催生教师视角/进度同步等新需求；顺带 → 从画像降级。）

## 4. 需求定稿后的教学路线（已向用户预告）

1. 把确认后的需求落盘为 `doc/ipad-cfd-teaching/requirements.md`（含编号，供追溯）。
2. 下一课：**需求 → 架构的推导方法**——讲「架构显著性需求（ASR）」筛法：为什么 NFR4（性能）、C1（不能动态编译）这类条目对架构的影响远大于 FR 清单；演示从需求表逐条推导出架构决策（可对照仓库中已有的 architecture.md 验证推导结果，但注意：那份文档对用户是新东西，引用须贴全文）。
3. 之后依次：②用例/领域建模 → ③架构设计（分层、ADR）→ ④接口与数据结构 → ⑤里程碑与垂直切片 → ⑥各阶段验证方法。每课先理论后实操。
