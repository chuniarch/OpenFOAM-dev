# iPad CFD 教学 App — 需求与架构 交接摘要

# 第一部分 · 需求（Requirements）

## 1. 产品定位
iPad 上的**教学型 CFD App**，定位为 **OpenFOAM 的「引桥课」**：让初学者**零环境成本**在 iPad 上走通一次「从输入到流场」的完整闭环，并能对照真实 OpenFOAM 源码，建立心智模型后再去面对真正的 OpenFOAM。

- **不替代** OpenFOAM，只攻它最薄弱的「上手第一公里」。
- **核心差异化** = 源码入门（看懂 OpenFOAM 的 C++），这是区别于其他 CFD 演示 App 的卖点。

## 2. 目标用户
CFD / OpenFOAM 初学者（学生、自学者、课堂场景）。特征：被 OpenFOAM 的环境配置与概念门槛劝退、但有 iPad、想低成本入门。

## 3. 为什么是 iPad（价值主张）
1. 便携，随时学习/演示。
2. 桌面 OpenFOAM 需 WSL/虚拟机/编译，初始门槛极高；iPad 一键安装。
3. 初学者用不到复杂功能，简化可降低心智负担。
4. 触屏即时反馈 + 「源码↔数学↔结果」三联动，是桌面端（命令行 + ParaView 割裂）给不了的新教法。
5. 可控、防挫败：预置稳定参数，保证必出结果，先给成就感。
6. 分发即触达：App Store 一键装，课堂可全班同步。

## 4. 功能需求
- **运行**：在端上求解一个 CFD 算例并出流场结果（首个 = 顶盖驱动方腔）。
- **编辑**：以图形/表单方式编辑算例输入（边界条件、参数），并能看到等价的 OpenFOAM 字典文本。
- **可视化**：速度矢量/流线、压力云图、残差/收敛曲线、随时间演化。
- **源码入门**：点 UI 上的某个概念/函数 → 看到对应的真实 OpenFOAM 源码 + 解释 + 数学公式。
- **交互式理解**：单步/播放求解过程；点某个网格单元查看其数值与离散细节。

## 5. MVP 范围（敢于砍）
- 只做**一个案例**：icoFoam + 2D 顶盖驱动方腔（cavity）。做到极致即可发布，之后按「加案例」迭代。
- 网格：2D 均匀方腔，保留 patch/边界概念，跳过复杂网格生成。
- 求解器：先一个（icoFoam）。
- 边界条件：覆盖 cavity 所需的几类即可（fixedValue、noSlip、zeroGradient、empty）。

## 6. 约束
- **平台**：iOS 可运行预编译 C++，但**不能**在设备上编译用户现写代码（App Store 2.5.2），也**不实际**整搬 OpenFOAM 本体（依赖 MPI/wmake/动态库选择）。
- **触屏**：无物理键盘时手敲字典体验差 → 输入须图形化。
- **许可**：OpenFOAM 为 **GPL v3**，与 App Store 分发条款冲突（见架构 §4）。
- **数值稳定性**：新手乱改参数易发散 → 需锁定安全参数范围。

# 第二部分 · 架构设计（Architecture）

## 1. 关键架构决策
| 决策 | 选择 | 理由 |
|---|---|---|
| 求解引擎 | **Swift** 重新实现极简内核 | 好调试/优化、无桥接复杂度、上架成熟；不搬 OpenFOAM 本体 |
| 源码展示 | 运行 Swift，但用户点函数时**展示真实 OpenFOAM C++ 源码** | OpenFOAM 本就是 C++，展示真源码即源码入门；运行与展示靠「函数↔源码映射表」对齐，二者语义须一致 |
| 案例组织 | **数据驱动、可插拔**（案例=输入数据+solver 标识，内核按数据驱动而非写死） | 加新案例=加数据，不动 UI/框架 |
| 公式渲染 | **SwiftMath**（原生、离线） | PDE 标准记号够用；复杂排版以后局部上 KaTeX/WebView |
| 可视化 | **Metal / SwiftUI Canvas** | 流场/云图/曲线 |

## 2. 分层架构
```
展示层  SwiftUI + Metal
  ├─ 案例编辑器（表单 ↔ 字典文本 双向同步）
  ├─ 源码面板（真实 OpenFOAM C++，行高亮）
  ├─ 数学面板（SwiftMath 渲染 PDE）
  ├─ 结果可视化（矢量/云图/流线/残差曲线）
  └─ 数据探针（点 cell 看数值与离散细节）
联动层  ViewModel（@Observable，单一事实源）
  └─ 驱动「点一处 → 多面板响应」
引擎层  Swift 求解内核（纯计算，零 UI 依赖，可单测）
资源层  案例数据 + 内嵌真实 OpenFOAM 源码片段 + 「函数↔源码」映射表
```
**纪律**：引擎层零 UI 依赖，可独立单测。

## 3. 展示面板与联动（UX 架构）
9 个面板，差异化王牌是前两个：
1. **数学↔代码桥**：点源码行 → 高亮对应 PDE 项。
2. **数据探针**：点 cell → 看该格的数值与离散贡献（把最难懂的隐式离散实体化）。
3. 源码面板　4. 速度矢量/流线　5. 压力云图　6. 残差/Courant 曲线
7. 字典编辑器（表单↔文本双向，既解触屏体验又是教学法）
8. 网格/patch 视图　9. 时间轴控制（播放/暂停/单步）

联动核心：**单一事实源**（当前高亮节点 / 迭代状态 / 选中 cell）驱动各面板自动刷新。「一处操作、多处响应」是教学 App 的灵魂。

## 4. GPL 许可（架构级约束）
- 风险：A 内嵌 OpenFOAM 源码片段、B 移植其架构（灰色）、C **GPL 与 App Store 冲突**（著名坑）。
- **当前决策**：原型期**先内嵌真源码开发、不分心**；**上架前**改造为 ①源码外链 openfoam.org + ②源码面板用自写的等价讲解，并确认整 App 分发许可。

## 5. 里程碑（产品演进路线）
- **M0** 引擎内核（已搭，代码在 FoamMini/，本线不深入）
- **M1** Metal 可视化（矢量/云图/残差 + 时间轴）
- **M2** 源码入门（源码面板 + 映射表 + SwiftMath + 数学↔代码桥）
- **M3** 数据探针 + 字典编辑器
- **M4** 打磨发布（引导教程、参数锁定、上架）
