## 0. 关键决策记录（需求方对齐的验证记录）

| 决策点 | 裁决 | 理由 / 后果 |
|---|---|---|
| **源码入门（FR4）是否核心差异化** | **保留为核心** | 接受其连带成本（源码面板、函数↔源码映射、公式渲染、点代码联动探针）+ GPL 债（C3）。是与普通 CFD 演示 App 的本质区别。FR4 还是 FR5、FR7 的依赖锚点（无源码切分则无可探查/可问对象）。 |
| **是否新增"保存/分享"** | **接受为 FR6，划出 MVP** | 形态 = 本地保存 + 分享，延后至 M5 之后的发布后迭代。做法见 §7。 |
| **学习路径：自由探索 vs 引导关卡** | **自由探索 + 最轻量首次引导** | 关卡系统是独立大功能；NFR2 用"必出结果 + onboarding 气泡"即可满足。 |
| **"课堂场景"是否设计目标** | **明确不做**（2026-06-11） | 唯一目标用户 = 单个自学者。课堂/多人/教师视角列入"不做"（§6）并记录决策以备追溯。 |
| **AI 源码问答（FR7）的地位与时机** | **升格为正式需求；与静态层平权；排期发布后第一迭代 M5** | 预写解释是作者视角、有限集；学习者问题是读者视角、**无限长尾**——静态内容接不住长尾，AI 才能，故二者价值**平权**。但 AI 上下文包（符号+源码+公式+预写解释）的地基是静态层，**先建静态非因更重要，而因它是 AI 的弹药库**；故交付时机后置而非价值后置。 |
| **是否新增"界面好看"需求** | **新增 NFR6（界面质量），不作 FR** | "好看"是质量属性（做到什么程度），属 NFR 不属 FR。"美"主观、不可客观验收；需求阶段只锁可验收的质量底线（HIG 遵从 + 可用性指标），美感留待 ③④ 设计稿评审收敛。 |

## 1. 愿景

iPad 上的**教学型 CFD App**，定位是 OpenFOAM 的「引桥课」：让初学者**零环境成本**在 iPad 上走通一次「从输入到流场结果」的完整闭环，并能**对照真实 OpenFOAM 源码**建立心智模型，然后再去面对真正的 OpenFOAM。

两条边界声明（防愿景漂移）：

- **不替代 OpenFOAM**，只解决"上手第一公里"。
- **核心差异化 = 源码入门**（教人看懂 OpenFOAM 的 C++），由**两根平权支柱**支撑：
  - **支柱一 · 静态对照**：源码 ↔ 数学公式 ↔ 运行结果 三联动（看懂"这行代码 = 哪个方程项 = 流场里哪块变化"）。离线可用。
  - **支柱二 · AI 答疑**：就眼前这段代码直接追问，承接静态解释触达不到的**长尾问题**（每个学习者背景不同、问题各异，作者无法预写穷尽）。在线。
  - 二者**价值平权**；静态层同时是 AI 上下文的**地基**（见 FR7、NFR5）。

## 2. 目标用户

**主体（唯一目标用户）：单个 CFD / OpenFOAM 初学者**（自学者、学生）。画像：被 OpenFOAM 的环境配置（WSL/虚拟机/编译）和概念门槛劝退过，但有 iPad，想低成本入门。

**课堂 / 多人场景：明确不做**（2026-06-11，见 §6）。不引入教师视角、全班进度同步、布置/批改等需求。

## 3. 功能需求（FR）

> 追溯纪律：每条 FR 配一条**验收方式**。`范围`列标明交付批次。

| 编号 | 需求 | 内容 | 验收方式 | 范围 |
|---|---|---|---|---|
| **FR1** | 运行 | 在 iPad 端上求解一个 CFD 算例并得到流场结果（首案例 = 2D 顶盖驱动方腔） | 对 cavity 跑到 `endTime`，涡心位置、残差收敛趋势与真实 icoFoam 一致 | ✅ MVP |
| **FR2** | 编辑 | 用图形/表单方式编辑算例输入（边界条件、参数），同时可见等价的 OpenFOAM 字典文本 | 改边界/参数 → 表单与 dict 文本双向同步 → 重算生效 | ✅ MVP |
| **FR3** | 可视化 | 速度矢量/流线、压力云图、残差/收敛曲线、流场随时间演化 | 四类视图随时间步刷新且数值正确 | ✅ MVP |
| **FR4** | 源码入门（静态支柱） | 点 UI 上的概念/函数 → 真实 OpenFOAM C++ 源码 + 解释 + 数学公式（源码↔公式↔结果三联动） | 点 `fvm.laplacian` 等 → 显示真实 `icoFoam.C` 对应行 + 公式 + 解释 | ✅ MVP |
| **FR5** | 交互式理解 | 单步/播放求解过程；点某个网格单元，查看它的数值和离散细节 | 能单步/播放 PISO；点某 cell 显示其 U/p 值与离散贡献（矩阵系数） | ✅ MVP |
| **FR7** | AI 答疑（AI 支柱） | 选中（点击/长按）源码中的函数/类 → 该片段（+解释/公式，将来可含求解状态）自动作为上下文注入 AI 对话框，免手敲代码即可追问 | 选中某符号 → AI 对话框已载入该上下文 → 可连续追问；断网时入口优雅降级（见 NFR5） | ⏳ M5（发布后第一迭代） |
| **FR6** | 保存/分享 | 保存改过的算例 + 结果快照到本地；可分享（导出图片/算例） | （随该里程碑细化；做法见 §7） | ⏳ M5 之后 |

## 4. 非功能需求（NFR）

> 决定架构的往往是这些条目。

| 编号 | 需求 | 内容 | 验收方式 |
|---|---|---|---|
| **NFR1** | 零环境成本 | App Store 一键安装，无任何配置 | 安装后无需任何额外步骤即可运行首个案例 |
| **NFR2** | 防挫败 | 预置稳定参数，保证新手必出结果，先给成就感 | 预置参数下 100% 出结果、零崩溃；危险参数被锁在安全范围（见 C4） |
| **NFR3** | 触屏友好 | 无键盘也能完成全部输入（故编辑须图形化，FR2 的由来） | 全部输入可仅用触屏（表单/滑杆/选择器）完成，无需物理键盘 |
| **NFR4** | 交互性能 | 求解和渲染流畅到支撑"实时观看、随时单步" | 教学网格（20×20）下求解+渲染流畅；单步响应无可感卡顿、可连续播放 |
| **NFR5** | 分层可用性 | **静态教学层**（求解、源码、公式、预写解释、可视化、探针）**离线必可用**；**AI 对话层**（FR7）在线，断网**优雅降级**（入口置灰+提示，核心不残废）。_本条是可用性底线，非价值排序——AI 与静态价值平权（见愿景）。_ | 飞行模式下静态层全部可用；AI 入口置灰且有明确提示，核心功能无残缺 |
| **NFR6** | 界面质量 | 遵循 Apple HIG；统一设计系统（字体/色板/间距）；触控目标 ≥ 44pt；适配 iPad 横屏多栏布局 | 设计评审通过；新手可用性测试：5 名新手 ≥4 名无指导下 10 分钟内完成"改边界→重算→看结果"（指标待校准） |

## 5. 约束（Constraints）

| 编号 | 约束 | 后果 |
|---|---|---|
| **C1** | App Store 规则 2.5.2：iOS 上不能编译用户现写的代码 | 求解器必须**预编译内置**；用户只能编辑**数据**（参数/边界），不能写代码 |
| **C2** | OpenFOAM 本体依赖 MPI/wmake/动态库机制 | 不现实整搬，引擎须**重新实现** |
| **C3** | OpenFOAM 是 GPL v3，与 App Store 分发条款冲突 | 内嵌源码片段有法律风险（原型期内嵌、上架前改造）；FR7 把源码发给第三方 AI 是又一接触点 |
| **C4** | CFD 数值方法本身会发散 | 新手乱改参数必炸 → 必须**锁定安全参数范围**（支撑 NFR2） |

## 6. 范围（交付批次）

**MVP（M0–M4，首发）做：**
- 一个案例（**icoFoam + 2D cavity**）做到极致；4 种 BC（`fixedValue`/`noSlip`/`zeroGradient`/`empty`）；2D 均匀方形网格。
- **静态支柱**完整（FR1–FR5）：源码↔公式↔结果三联动、单步、探针。
- **最轻量首次引导**（onboarding 气泡，非关卡系统）。
- 满足 NFR1–NFR6（含界面质量底线）。

**发布后迭代：**
- **M5（发布后第一迭代，最高优先）：FR7 AI 答疑支柱**。价值与静态平权，仅交付时机后置——AI 上下文依赖静态层先成形（地基顺序，非价值后置）。
- **M5 之后：FR6 保存/分享**。

**第一版明确不做：**
- 3D、湍流、复杂网格生成、多求解器、用户自定义案例。
- **引导式教程关卡系统**（2026-06-10：走自由探索）。
- **课堂 / 多人协作 / 教师视角**（2026-06-11：唯一目标用户 = 单个自学者）。

**演进策略：** 架构上要求"**加新案例 = 加数据，不改框架**"。

## 7. 延后项的做法概述（仅在"需求高度"上澄清，不下沉实现）

### FR7 AI 答疑 —— 做法 + 已决取舍（正式需求，排期 M5）

- **做法**：FR4 已把源码按函数/类切分并建"函数↔源码映射表"（每符号挂片段+解释+公式）。在此之上：点击/长按函数/类名 → 取其关联上下文（源码片段 + 解释/公式，将来可含当前求解状态）自动注入 AI 对话框 → 用户直接在引用后追问，免手敲大段代码。复用 FR4 切分基础设施，是"读源码"到"就源码对话"的升级；增量成本主要在 AI 后端一侧。
- **价值定位**：与静态对照**平权**，专攻静态预写内容接不住的**长尾问题**（读者视角、无限、因人而异）。**先建静态层不是因为它更重要，而是因为它是 AI 上下文包的地基与弹药库**——没有切分/映射/预写解释，"App 内 AI"就退化成"自己开聊天网页手动贴代码"，App 毫无增值。
- **离线取舍（已决，见 NFR5）**：核心静态层离线必可用；AI 对话层在线、断网优雅降级。这是可用性分层，不是价值排序。
- **GPL（接 C3）**：真实源码作上下文发给第三方 AI 是又一接触点，并入上架前评估；若届时改"自写等价讲解"作展示内容则规避。
- **次生需求**：隐私披露（向第三方发提问+代码，App Store 声明）；AI 账号/费用/限流；答案与所展示源码语义的一致性。

### FR6 保存 / 分享 —— 怎么做（概念层）

- **保存**：把当前算例输入（边界/参数）+ 结果快照（某时刻流场 + 残差曲线）序列化到设备本地沙盒，可重载回看。**不依赖网络**。
- **分享**：导出可传递产物——① 图片/动画（最简单、零隐私顾虑）；② 算例文件（让对方载入复现，需稳定导出格式 + 版本兼容）。经系统分享面板发出。
- **次生需求**：导出格式与版本兼容；导入校验；隐私边界；跨设备同步（属更大决策）。

## 8. 追溯关系（可追溯纪律）

- **需求 → 验收**：见 §3 / §4 各条"验收方式"列。
- **需求间派生/依赖**：FR2（图形化编辑）由 **NFR3 ∧ C1** 派生；NFR2 由 **C4** 支撑；FR5、FR7 依赖 **FR4**（无源码切分则无可探查/可问对象）；**FR7 的上下文质量依赖静态层先成形**（决定建造顺序）。
- **需求间冲突（已解）**：FR7（在线）与"离线"的张力，由 **NFR5 改写为分层可用性**化解（静态离线、AI 在线降级），非价值取舍。
- **需求 → 架构**（下一步建立）：架构每个模块须能指回本表某条需求；推导方法见"需求→架构（ASR 筛法）"一课，验证目标为 `doc/ipad-cfd-teaching/architecture.md`。
- **需求 → 界面**（②阶段建立）：由 FR 推导用例、再推导界面清单（含 AI 对话面板 ←FR7），与 `architecture.md §6` 的 9+1 面板草案对账。
