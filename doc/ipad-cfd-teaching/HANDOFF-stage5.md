## 0. 给接手模型的关键指示（务必先读）

1. **用户身份**：需求方 + 学习者（自述软件工程"几乎全忘"、**不是工程师**、**目前还不懂 OpenFOAM 代码和 Swift**）。⑤ 是写代码，但**必须边写边教**：先大白话讲"这段在干嘛 / 为什么"，再写；每段代码配注释式讲解。
2. **★教学高度——本线最大教训★**：④ 阶段用户明确说过"**完全不懂每个类/结构体/函数的实际作用**"。⑤ 要**逐行教、边写边懂**，**严禁工程师对工程师式堆术语**。判据：用户能用自己的话复述"这段代码在干嘛"。一次只啃一小块。
3. **★全文呈现纪律★**：重要内容必须完整写在对话里；引用文档章节（如「④-1」「§15」）前先贴全文。
4. **★编号别撞号★**：三套编号分开——`①–⑥` 软件工程**大阶段**（现在 ⑤）/ `M0–M5` 产品**里程碑** / `④-1..④-7`（④内部，已冻结）。⑤ 如开内部清单，用 `⑤-1/⑤-2…` 或字母。
5. **★实操环境（关键）★**：⑤ 是真正写代码、要**编译、要跑**。
   - **整个 App（SwiftUI+Metal）只能在 Mac + Xcode 上编译运行**；纯引擎 `FoamMini`（SwiftPM 包）可在 **Mac 或 Linux + Swift 5.9+** 上 `swift build && swift test`。
   - ⚠️ **此前所有云端会话无 Swift 工具链，FoamMini 从未编译过**。⑤ **第一件事**就是在能编译的机器上把 M0 跑通、**按报错逐个修**（首次构建必有错，正常）。
6. **协作风格**：理论先行；用本项目真实材料做实例；**关键选型交用户拍板**；每次产出**落盘 + 全文呈现 + commit/push**。
7. **看不懂代码时的退路**：用户可随时去走 `openfoam-reading-plan.md`（P·理论 + P0–P6，先 FoamMini Swift 后真 OpenFOAM C++）补背景；⑤ 与它可交替进行。

## 4. ⑤ 的验证方式（"可验收"登场）

- **T1–T7 在 ⑤ 变成真能跑的测试**（③④ 只能评审）。每块实现 → 写对应判据的 XCTest → 跑绿 → 才算完。
- **红-绿-重构**：先写会失败的测试(红) → 实现到通过(绿) → 保持绿的前提下清理(重构)。
- **T5 守门**：任何对引擎的重构，必须保证"单步 n 次 == 连跑 n 步**逐位一致**"（④-1 已给黄金对拍判据 G1）。
- 各 ④ 块的 §x.8/x.9「可测试性判据」就是写测试的清单（G1、T6、S1–S4、T7、T2/T3/T4 等）。
