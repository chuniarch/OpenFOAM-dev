第 7 课 · 砖块 7 · Diffusion2D.ts

从一排到一片

一排盒子变成一片。每个盒子的邻居从两个变成四个，算法一点不变。这一课讲二维要改哪几处、TypeScript 里怎么建一张表，再给五把尺子——其中一把不解方程就能说出中心的值。

读约 15 分钟 + 写代码前置：第 6 课的一维程序（第八节折叠了一份）产出：Diffusion2D.ts

一 · 先定验收尺子

五把尺子共同的条件：

5 × 5 个盒子，正方形格子（Δx = Δy）
内部墙权重 k（左右、上下都一样）
边界墙权重 2k（盒子中心到边界墙只有半格：D × A / (Δx/2) = 2k）
初值全 0；高斯-塞德尔，最大改动 < 1e-6 就停

遍数是我这边的程序跑出来的，只作对照，差一两遍不算错（取决于"是否该停"的判断写在哪）。我按一行一行扫（外层 j、内层 i），也试过一列一列扫，这四道题的遍数都一样。

尺子一：为什么每一行都是 9、7、5、3、1

先看一维那道题：5 个盒子排成一排，左墙钉死 10，右墙钉死 0，内部墙 k，边界墙 2k。把答案 9、7、5、3、1 代回更新式 C_P = 分子 / 分母，每个盒子都算回自己：

1 号：(2k × 10 + k × 7) / (2k + k)  = 27k / 3k = 9
2 号：(k × 9 + k × 5) / (k + k)     = 14k / 2k = 7
3 号：(k × 7 + k × 3) / (k + k)     = 10k / 2k = 5
4 号：(k × 5 + k × 1) / (k + k)     =  6k / 2k = 3
5 号：(k × 3 + 2k × 0) / (k + 2k)   =  3k / 3k = 1

二维里让每一行都等于这一排。逐个盒子算净流入（每一面墙的 w × (对面的值 − 自己的值) 加起来）：

  • 上下两面：上下邻居和自己在同一列，值相同，流进量 k × (C_上 − C_P) = 0、k × (C_下 − C_P) = 0。最上面、最下面一行贴着的是不透水的墙，那一面本来就不写。
  • 左右两面：和一维那一排里同一个位置的盒子一模一样，上面五行算式说明它们加起来是 0。

所以 25 个盒子的净流入都是 0。重算一个盒子时，新值 − 现在的值 = 净流入 ÷ 分母（插页 C 推过：Σ(w × C_对面) / Σw − C_P = Σ w × (C_对面 − C_P) / Σw），净流入是 0，改动就是 0。每个盒子都算回自己，高斯-塞德尔就停在这里。

答案和一维一样，遍数却多（一维是 37 遍）。第一遍的第一个盒子就走得不一样：

二维 c[0][0]：左墙钉死 10（2k），右邻 c[0][1] = 0（k），上邻 c[1][0] = 0（k），下墙不透水（不写）
             (2k × 10 + k × 0 + k × 0) / (2k + k + k) = 20k / 4k = 5.000
一维 1 号：   (2k × 10 + k × 0) / (2k + k)           = 20k / 3k = 6.667

扫第 0 行时，上面的第 1 行还是初值 0，它通过那道内部墙把第 0 行往下拉；一维没有这一项。到了答案，上下相等，这一项才变成 0。

尺子二：为什么全是 5

每个盒子都代 5：每一面墙的流进量都是 w × (5 − 5) = 0，净流入 0，重算还是 5。

尺子三：为什么上下对称

把整张图上下翻过来：下墙和上墙对调，两面都是钉死 0，没变；左墙、右墙翻过来还是它们自己。题目一点没变，答案也就不能变，所以翻过来的表必须和原来的表相等：第 0 行 = 第 4 行，第 1 行 = 第 3 行。

"答案不能变"要求这组方程只有一组解。理由：假如有两组解，把它们逐格相减，得到的差也满足同样的 25 个方程，只是每面钉死的墙都变成了 0（10 − 10 = 0，0 − 0 = 0；插页 B 推误差的方程时就是这样两式相减的）。按下面尺子五的极值原理，这个差夹在最低墙值 0 和最高墙值 0 之间，只能处处是 0，两组解其实是同一组。

正中心的 2.500 见第五节：这道题是尺子四的图转了 90°。

尺子四：中心 2.500

推导在第五节。"每一行左右对称"的理由和尺子三一样：左右翻过来，左墙、右墙都是钉死 0，题目不变。

尺子五：极值原理

更新式 C_P = Σ(w × 对面的值) / Σw，就是一个盒子四面的值（邻居的值，或钉死的墙值）按权重取的平均；不透水的墙不参加。平均值不会比被平均的数里最大的那个还大。如果全场最大的值落在某个盒子上，它四面的值都得和它一样大，否则平均不到这么大；这样一格一格传出去，总会传到一个贴着钉死墙的盒子，那面墙的值也得和它一样大。所以盒子里的最大值不会超过最高的墙值，最小值也不会低于最低的墙值。超出去一定是 bug。

二 · 一维程序做了什么，二维改哪里

第 6 课的一维程序（全文折叠在第八节）里，每个盒子做的事：

分子 ← 0，分母 ← 0
看左边：是邻居          → 分子 += k × C_邻居，分母 += k
        是钉死浓度的墙  → 分子 += 2k × C_墙， 分母 += 2k
        是不透水的墙    → 什么都不加
看右边：同样三种情况，和看左边是两个独立的判断
新值 ← 分子 / 分母

外面套高斯-塞德尔：初值全 0；从第一个盒子到最后一个，逐个算新值，算完立刻写回数组；记下这一遍最大的 |新值 − 旧值|；小于 1e-6 就停，否则再扫一遍；最多扫 100000 遍（保险丝：写错时不至于永远转下去）。

一维（第 6 课）二维（这一课）
每个盒子的邻居左、右左、右、下、上
墙左墙、右墙左、右、下、上四面墙
存浓度的数组一排 number[]一张表 number[][]（行 × 列）
每个盒子里的判断2 个独立判断4 个独立判断
每个判断里的三种情况不变
高斯-塞德尔、最大改动、容差、保险丝不变

守恒律是骨架，维度只决定求和里有几项。从第八节那份一维程序改起，不要从头写。

这一课只用正方形格子（Δx = Δy），这样四个方向的内部墙权重都是同一个 k = D × A / Δx。格子不是正方形时，横竖两个方向的 k 不一样，那是以后的事。

三 · 下标约定和一张表

c[j][i]        j = 第几行（y 方向，往上数）    i = 第几列（x 方向，往右数）

左邻  c[j][i−1]        右邻  c[j][i+1]
下邻  c[j−1][i]        上邻  c[j+1][i]

TypeScript 里一张 n × n 的表，是"一排数组组成的数组"：

const n = 5;
const c: number[][] = Array.from({ length: n }, () => new Array(n).fill(0));
c[2][4] = 1.5;          // 第 2 行、第 4 列（都从 0 数）

Array.from({ length: n }, 函数) 把后面那个函数调用 n 次，每次返回的新数组当一行，所以 n 行是 n 个各自独立的数组。

看起来一样，其实是同一行

另一种写法少打几个字，但是错的。我在这边跑过：

const bad: number[][] = new Array(3).fill(new Array(3).fill(0));
bad[0][0] = 1;
console.log(bad.map((row) => row.join(" ")).join("\n"));
// 打印出来：
// 1 0 0
// 1 0 0
// 1 0 0        ← 只改了第 0 行，三行都变了

fill(x) 把同一个 x 放进每一格。x 是一个数组时，每一行拿到的都是它本身，不是复印件，三行其实是同一个数组。TypeScript 不会报错，类型照样是 number[][]。建表只用上面 Array.from 那一种写法。

最常见的错：行列用反

求解时用 c[i][j]、打印时用 c[j][i]（或者反过来）。程序照样能跑、不报错，只是打出来的整张表沿对角线翻了过去——左右的墙看起来变成了上下的墙。尺子三能抓它。约定只定一次，全程照用。

打印时从最上面一行往下打：for (let j = n - 1; j >= 0; j--)。这样屏幕上的"上"才是物理上的"上"；不然数值没错，但你看对称会看反。

四 · 边上的盒子、角上的盒子

中间的盒子四面都是邻居。贴着一面墙的盒子：三个邻居加一面墙。角上的盒子：两个邻居加两面墙。

所以每个盒子里是四个互相独立的判断：看左、看右、看下、看上，各自决定"是邻居还是墙"。一维程序里"看左边""看右边"就是两个分开的 if，不是 if … else：只有 1 个盒子、左墙钉死 10、右墙钉死 0 时，它两边都是墙，两个判断都要走到，才得到 (2k × 10 + 2k × 0) / (2k + 2k) = 5。

例：左下角的盒子 c[0][0]，左墙钉死 10，下墙钉死 0：

看左：是墙，钉死 10      分子 += 2k × 10      分母 += 2k
看右：是邻居 c[0][1]     分子 += k × c[0][1]  分母 += k
看下：是墙，钉死 0       分子 += 2k × 0       分母 += 2k
看上：是邻居 c[1][0]     分子 += k × c[1][0]  分母 += k
                                              ─────────
                                              分母 = 6k

容易写出来的错法，是按"这个盒子在哪条边上"写成一条 if … else if 链：

if (i === 0)          { 左墙 + 右邻 + 上下有邻居就算邻居 }
else if (i === n − 1) { 右墙 + 左邻 + 上下有邻居就算邻居 }
else if (j === 0)     { 下墙 + 左右邻居 + 上邻 }
else if (j === n − 1) { 上墙 + 左右邻居 + 下邻 }
else                  { 四个邻居 }

左下角 c[0][0] 进了第一个分支，就不会再进第三个，下墙那一项漏了；另外三个角也各漏掉上墙或下墙。我照这个写法跑过尺子四：中心是 2.182，不是 2.500。

五 · 尺子四：不解方程就知道中心是 2.5

上墙钉死 10、另外三面钉死 0，正中心的盒子是多少？把它和另外三道题放在一起看。四道题都是 5 × 5、内部墙 k、边界墙 2k，只差哪一面墙是 10：

上 10 题：上墙 10，左、右、下墙 0      它的解（一张 5 × 5 的表）记作 T
右 10 题：右墙 10，另外三面 0          解记作 R
下 10 题：下墙 10，另外三面 0          解记作 B
左 10 题：左墙 10，另外三面 0          解记作 L

第①步：四个解加起来，是"四面都钉死 10"那道题的解

拿左上角的盒子 c[4][0] 看：左边、上边是墙，右邻 c[4][1]，下邻 c[3][0]。它在四道题里的"进 = 出"（净流入 = 0），都按"左墙、上墙、右邻、下邻"的顺序写。T 是 T 表里这个盒子的值，T右、T下 是 T 表里它右邻、下邻的值，其余同理：

上 10 题：2k × (0 − T)  + 2k × (10 − T) + k × (T右 − T) + k × (T下 − T) = 0
右 10 题：2k × (0 − R)  + 2k × (0 − R)  + k × (R右 − R) + k × (R下 − R) = 0
下 10 题：2k × (0 − B)  + 2k × (0 − B)  + k × (B右 − B) + k × (B下 − B) = 0
左 10 题：2k × (10 − L) + 2k × (0 − L)  + k × (L右 − L) + k × (L下 − L) = 0

四式相加，按列合并。记 S = T + R + B + L（S 表是四张表对应位置相加），S右 = T右 + R右 + B右 + L右，S下 同理：

左墙那一列：2k × (0 − T) + 2k × (0 − R) + 2k × (0 − B) + 2k × (10 − L)
          = 2k × (0 + 0 + 0 + 10 − T − R − B − L) = 2k × (10 − S)
上墙那一列：2k × (10 − T) + 2k × (0 − R) + 2k × (0 − B) + 2k × (0 − L) = 2k × (10 − S)
右邻那一列：k × (T右 + R右 + B右 + L右 − T − R − B − L)              = k × (S右 − S)
下邻那一列：                                                          k × (S下 − S)

合起来：2k × (10 − S) + 2k × (10 − S) + k × (S右 − S) + k × (S下 − S) = 0

这正是"四面墙都钉死 10"那道题里左上角盒子的方程。换成别的盒子也一样：每一项都是"权重 × (对面 − 自己)"，权重在四道题里相同，可以提出来合并；每一面墙在四道题里恰好有一道是 10、三道是 0，加起来是 10。所以 S 表满足"四面都钉死 10"的全部 25 个方程。那道题的答案按尺子二的理由是处处 10（每面墙的流进量 w × (10 − 10) = 0），所以 S 表处处是 10。

这一步靠的是权重不随浓度变。要是扩散系数 D 跟着浓度变，k = D × A / Δx 在四道题里就各不相同，不能提出来合并，这一步就不成立。

第②步：四个中心值相同

把上 10 题的整张图顺时针转 90°：上墙转到右边，就是右 10 题。格子是正方形，内部墙都是 k、边界墙都是 2k，转过去之后每个盒子、每道墙的权重都对得上，所以 T 表转 90° 就是 R 表。正中心的盒子 c[2][2] 转完还在正中心，所以 T 表和 R 表在中心的值相同。再转两次得到 B 表和 L 表，道理一样。四个中心值相同，记作 x。

第③步：解出 x

S 表在中心：T中 + R中 + B中 + L中 = x + x + x + x = 4x = 10
            x = 2.5

你的程序算出来必须是 2.500。中心要真的是一个盒子，所以每边的格子数取奇数，5 × 5 正好。尺子三（左墙钉死 10）就是左 10 题，所以它的中心也是 2.500。

六 · 易错点

  1. c[i][j] 和 c[j][i] 混用 → 整张表沿对角线翻过去。尺子三能抓：第 0 行和第 4 行不再相等。
  2. 四个判断写成 if … else if 链 → 角上的盒子少算一面墙。尺子四能抓：中心不再是 2.500。
  3. 用 new Array(n).fill(new Array(n).fill(0)) 建表 → 所有行是同一个数组，打出来每一行一模一样。尺子一抓不住它（练习第 5 题讲为什么），尺子三、四抓得住。
  4. 从 j = 0 开始打印 → 屏幕上下颠倒。数值没错，但看对称会看反。
  5. 算出新值却忘了写回 c[j][i] → 永远是初值。尺子一的症状：25 个全是 0.000，每一遍的最大改动都停在 5.000（c[0][0] 每一遍都从 0 算出 5.000，却没存进去），只能等保险丝。你上一轮写二维版时踩过这个。
  6. 最外层把上墙叫 top → 网页里的 Playground 会标红「Cannot redeclare block-scoped variable」（不能重复声明）：浏览器已经有一个全局变量叫 top。改个名字（比如 topWall），或者把四面墙当作函数参数传进去。
  7. 从头重写而不是在一维程序上改 → 一维里已经修好的错，会在这里再犯一遍。

八 · 起点：一维程序 Diffusion1D.ts

第 6 课参考答案的 TypeScript 版。先把它整个贴进 Playground 跑一遍，确认看到下面那段输出，再动手改成二维。要改的地方：数组换成一张表，"看左、看右"扩成"看左、看右、看下、看上"，墙从两面变成四面，打印换成一张表从最上面一行往下打。

展开 Diffusion1D.ts 全文 
// ============================================================
// Diffusion1D.ts  —— 砖块 6：一维稳态扩散 + 高斯-塞德尔
//
// 物理：一排 N 个盒子，水静止，墨只靠扩散在盒子之间移动。
//       两端各一面边界墙：钉死浓度的墙，或不透水的墙。求稳态。
// 数学：每个盒子一条方程  C_P = 分子 / 分母
//       内部墙：        分子 += k·C_邻居    分母 += k      k = D·A/Δx
//       钉死浓度的墙：  分子 += 2k·C_墙     分母 += 2k     （盒心到墙只有半格）
//       不透水的墙：    什么都不加
//       解法：高斯-塞德尔，算出新值立刻写回；最大改动 < 容差 就停。
// 运行：贴进 TypeScript Playground 点 Run；或在电脑上 node Diffusion1D.ts
//       （Node 22.18 或更新的版本能直接跑 .ts 文件）。
// ============================================================

// ===== 1. 墙的描述 =====
// 联合类型：一面墙要么是「钉死的，带一个值」，要么是「不透水的，什么都不带」。
type Wall =
  | { kind: "fixed"; value: number } // 钉死浓度的墙，带着墙上的浓度 [kg/m³]
  | { kind: "closed" };              // 不透水的墙

function fixedWall(value: number): Wall {
  return { kind: "fixed", value: value };
}
const closedWall: Wall = { kind: "closed" };

// ===== 2. 求解器 =====
// 返回：每个盒子的浓度 [kg/m³]，以及一共扫了几遍。
// 两面墙都不透水时方程没有唯一解，本程序不处理这种设定。
function solveDiffusion1D(
  n: number,             // 盒子个数
  length: number,        // 全长 L [m]
  diffusivity: number,   // 扩散系数 D [m²/s]
  area: number,          // 墙的面积 A [m²]
  left: Wall,
  right: Wall,
  initialGuess = 0.0,
  tolerance = 1e-6,
  maxSweeps = 100_000,   // 保险丝：写错时不至于永远转下去
): { c: number[]; sweeps: number } {

  if (!Number.isInteger(n) || n < 1) {
    throw new Error("至少要有一个盒子");
  }

  const dx = length / n;                 // 格宽 Δx [m]
  const k = diffusivity * area / dx;     // 内部墙权重 [m³/s]

  const c: number[] = new Array(n).fill(initialGuess);
  let sweeps = 0;

  while (sweeps < maxSweeps) {
    sweeps += 1;
    let maxChange = 0.0;                 // 每一遍开头清零

    for (let i = 0; i < n; i++) {
      let numerator = 0.0;               // 分子
      let denominator = 0.0;             // 分母

      // 看左边：是邻居还是边界墙
      if (i > 0) {
        numerator += k * c[i - 1];
        denominator += k;
      } else {
        switch (left.kind) {
          case "fixed":
            numerator += 2.0 * k * left.value;
            denominator += 2.0 * k;
            break;
          case "closed":
            break;
        }
      }

      // 看右边：和看左边是两个独立的判断（只有一个盒子时，两边都是墙）
      if (i < n - 1) {
        numerator += k * c[i + 1];
        denominator += k;
      } else {
        switch (right.kind) {
          case "fixed":
            numerator += 2.0 * k * right.value;
            denominator += 2.0 * k;
            break;
          case "closed":
            break;
        }
      }

      const newValue = numerator / denominator;
      maxChange = Math.max(maxChange, Math.abs(newValue - c[i]));
      c[i] = newValue;                   // 就地写回：后面的盒子马上用上新值
    }

    if (maxChange < tolerance) {
      break;
    }
  }

  return { c: c, sweeps: sweeps };
}

// ===== 3. 打印 =====
function report(title: string, result: { c: number[]; sweeps: number }): void {
  const values = result.c.map((v) => v.toFixed(3)).join(" ");
  console.log(`${title}：${values}   （扫了 ${result.sweeps} 遍）`);
}
