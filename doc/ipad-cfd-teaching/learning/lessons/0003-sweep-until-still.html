一遍遍逼近

砖块 3 说五条方程咬在一起、必须一起解，却一直没说怎么解。答案出奇地简单：先随便猜，再把砖块 2 的式子一遍遍套上去。学完你能手算几遍，并且知道什么时候该停。

约 8 分钟前置：砖块 2、3、5没有新公式

三十秒回顾

砖块 5 的情形甲：一排 5 个盒子，左墙钉死 10，右墙钉死 0。五条方程是：

C_1 = (20 + C_2) / 3        ← 左墙是边界（2k）
C_2 = (C_1 + C_3) / 2
C_3 = (C_2 + C_4) / 2
C_4 = (C_3 + C_5) / 2
C_5 = C_4 / 3               ← 右墙是边界（2k）

答案我们已经知道：9, 7, 5, 3, 1（钉在两面墙上的直线）。这一课正好拿它当标准答案，看看新方法能不能自己找到它。

砖块 3 卡住的地方：算 C_1 要先知道 C_2，算 C_2 又要先知道 C_1。每个盒子都在等别人。

一 · 打破死结：先猜

死结的破法是：不等了。

  1. 先给每个盒子随便填一个数 —— 比如全填 0。
  2. 假装邻居现在的值是对的，按上面的式子算自己。
  3. 五个盒子都算一遍，叫做扫一遍。
  4. 再扫一遍，再扫一遍……

第一遍算出来当然不对 —— 邻居本来就是猜的。但它会比猜的更接近。下一遍又更近一点。

注意：这里没有任何新公式。每一步用的都是砖块 2 的"等于邻居的加权平均"，只是反复地用。

二 · 手算第一遍

从全 0 开始，从左往右，一个一个算：

  1. 1 号 
    C_1 = (20 + C_2) / 3 = (20 + 0) / 3 = 6.667
  2. 2 号 —— 注意这里用的 C_1 
    C_2 = (C_1 + C_3) / 2 = (6.667 + 0) / 2 = 3.333

    用的是刚刚算出来的 C_1 = 6.667，不是一开始猜的 0。算出一个新值就立刻写回去，后面的盒子马上用上。

  3. 3、4、5 号，同样的做法 
    C_3 = (3.333 + 0) / 2 = 1.667
C_4 = (1.667 + 0) / 2 = 0.833
C_5 = 0.833 / 3       = 0.278

这种"算完立刻写回、马上给下一个用"的做法，叫高斯-塞德尔（Gauss-Seidel，两个人名，不用记）。

第二遍照样从 1 号开始，只是现在邻居都有值了。比如 1 号：(20 + 3.333) / 3 = 7.778 —— 用的是第一遍算出的 C_2。继续扫下去：

三 · 什么时候停

真实问题里我们不知道答案 —— 知道的话就不用算了。所以没法直接量"离答案还有多远"。

但有一样东西量得出来：这一遍里，改动最大的那个盒子改了多少。上表最后一列就是它。

停止规则

事先定一个很小的数，叫容差（比如 1e-6，即百万分之一）。某一遍的最大改动小于容差，就停。

情形甲：第 37 遍的最大改动是 0.00000076，小于 0.000001，停。此时五个数就是 9.000, 7.000, 5.000, 3.000, 1.000。

看最后一列还能发现一件事：头几遍改得很猛，后面越改越少。第 1 遍改了 6.667，第 20 遍只改 0.001。这为什么会这样、能不能加快，是后面插页 B 的内容；现在只需要注意到它。

四 · 验收尺子

尺子一：必须停在已知答案上

情形甲必须收敛到 9, 7, 5, 3, 1。这是砖块 5 的尺子一，现在拿来检查解法。

尺子二：初值无关

从全 0 出发要扫 37 遍，从全 100 出发要扫 45 遍，但最后停在同一组数上。两端墙钉死了值，方程组的解就只有一组；初值只影响要扫几遍。如果两个初值停在不同的地方，程序有 bug。

尺子三：改动总体越来越小

这个问题用这种方法一定会收敛。如果你的程序越扫改动越大，或者冒出 NaN（"不是一个数"，除以零之类会产生它），一定是写错了 —— 最常见的是把新值写进了错的盒子。

五 · cavity 里真的在跑这个

本仓库 cavity 算例的 system/fvSolution 里，速度 U 的求解器设置是：

U
{
    solver          smoothSolver;
    smoother        symGaussSeidel;      ← 就是这一课的高斯-塞德尔
    tolerance       1e-05;               ← 就是这一课的容差
}

它真正执行的代码在 src/OpenFOAM/matrices/lduMatrix/smoothers/symGaussSeidel/symGaussSeidelSmoother.C。核心循环去掉细节后是这样（C++，不用会写，认结构就行）：

for (celli = 0; celli < nCells; celli++)            // 从第一个盒子到最后一个，逐个来
{
    psii = bPrimePtr[celli];                          // 分子：已知部分（含左边邻居的新值）
    psii -= upperPtr[facei]*psiPtr[uPtr[facei]];      // 分子：加上右边邻居的 w × C（还没轮到，用旧值）
    psii /= diagPtr[celli];                           // 除以分母 Σw
    bPrimePtr[uPtr[facei]] -= lowerPtr[facei]*psii;   // 把刚算出的新值，马上交给右边邻居
    psiPtr[celli] = psii;                             // 就地写回
}
// 然后从最后一个盒子往回再扫一遍 —— sym（对称）就是来回各一遍

第二行的"减号"其实是加：矩阵里邻居的系数存的是 −w（回忆砖块 3 的矩阵：对角线 +2，邻居 −1），减去 −w × C 就是加上 w × C。

对照你刚才的手算：分子除以分母、算完立刻写回、右边的盒子马上用上新值——一模一样。OpenFOAM 判停时量的是"残差"（把当前值代回方程还差多少），不是"最大改动"，但思路相同：量一个量得出来的东西，小于容差就停。
