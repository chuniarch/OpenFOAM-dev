3平场：两面墙都钉死 5，初值全 0全是 5.000分母漏加
4情形甲，把扩散系数 D 放大 100 倍和第 1 条一个数字都不差权重没有统一用 k

遍数差一两遍不算错——取决于你把"是否该停"的判断写在循环的哪个位置。差得多才要查。

第 4 条为什么成立

稳态方程里每一项都乘着同一个 k，而 k = D·A/Δx 里有 D。算 分子 / 分母 时，k 上下约掉，D 也就跟着没了。

物理意思

D 决定墨水多快到达稳态，不决定稳态在哪。现在我们只算"最后停在哪"，所以 D 不起作用。到砖块 8 算"随时间怎么变"时，它就要起作用了。

那门图形课的做法是"先写测试、看它红、再写代码让它变绿"。上面这张表就是同一个思路，只是不用测试框架——你自己对照输出。

二 · 四层翻译

写任何求解器都按这四层走，不许跳级：碰键盘之前，前三层要先想清楚。

第一层 · 物理

一排 N 个盒子，两面墙，稳态，墨从浓流向淡。你已经会了。

第二层 · 数学

每个盒子一条方程：C_P = 分子 / 分母。内部墙贡献 k·C_邻居 和 k；钉死浓度的墙贡献 2k·C_墙 和 2k；不透水的墙什么都不贡献（砖块 2、5）。然后高斯-塞德尔扫到最大改动小于容差（插页 A）。你也已经会了。

第三层 · 数据结构：要存哪些东西

先自己想一下再往下看。

  • 一个长度 N 的数组，存每个盒子的浓度
  • 左墙、右墙各一个"墙的描述"：哪种墙？如果是钉死的，值是多少？
  • 内部墙的权重 k，由 D、A、Δx = L / N 算出来
  • 容差，以及"最多扫几遍"——一根保险丝

第四层 · 代码结构（用话说，Swift 你来写）

准备：算出 Δx 和 k；数组填上初始猜测

重复，直到「最大改动 < 容差」或「扫满保险丝上限」：
    最大改动 ← 0                              ← 每一遍开头清零
    对每个盒子 i，从第一个到最后一个：
        分子 ← 0，分母 ← 0
        看左边：i 是第一个盒子吗？
            不是 → 左边是邻居，按内部墙算
            是   → 左边是边界墙，按墙的种类算
        看右边：i 是最后一个盒子吗？（同理）
        新值 ← 分子 / 分母
        最大改动 ← max(最大改动, |新值 − 旧值|)
        把新值写回数组                          ← 别忘了

打印：每个盒子的值、一共扫了几遍

注意"看左边"和"看右边"是两个独立的判断，不是 if/else 二选一。只有一个盒子时，它两边都是边界墙——尺子 5 专门查这个。

三 · 要用到的 Swift

下面每一段只演示一个语法点，不是你的程序。你把它们组合起来。

import Foundation                     // 要用 String(format:) 就得先写这行

let n = 5                             // let：定了就不再改
var total = 0.0                       // var：之后要改；写 0.0 而不是 0，Swift 才知道是小数
let x = 1.0 / Double(n)               // Int 和 Double 不会自动换算，必须写 Double(...)

var c = [Double](repeating: 0.0, count: n)   // 长度 n、全是 0.0 的数组
c[0] = 3.5                            // 下标从 0 开始；数组要改内容，就必须用 var 声明

for i in 0..<n { print(i) }           // 依次打印 0, 1, …, n−1（不含 n）
while total < 10.0 { total += 1.0 }   // 条件成立就一直做

let bigger = max(2.0, 3.0)            // 两数取大
let size = abs(-4.2)                  // 绝对值

print(String(format: "%.3f", 9.0))    // 保留三位小数输出：9.000

墙的描述：推荐用 enum

enum Wall {
    case fixed(Double)     // 钉死浓度的墙：带着墙上的值
    case closed            // 不透水的墙：什么都不带
}

let left = Wall.fixed(10.0)
let right = Wall.closed

switch left {
case .fixed(let value):    // 是钉死的墙，顺便把值取出来叫 value
    print("钉死在", value)
case .closed:              // 是不透水的墙
    print("不透水")
}

（每个 case 下面至少要有一条语句，只写注释会编译报错。）

推荐它的理由是：数据的形状和物理一致——只有钉死的墙才有一个值，不透水的墙根本没有值，enum 能把这件事写进类型里。用两个 Bool 加两个 Double 也能写，先跑起来最重要。

四 · 易错点

  1. 算出新值却没写回数组 → 永远是初始猜测。你上一轮写二维版时就踩过这个（记在 README 砖块 7 条目里）。
  2. "最大改动"每一遍开头没清零 → 它一直记着第一遍的大数，永远停不下来。
  3. 把第一个盒子的值当成墙上的值 → 第一个盒子输出 10，应该是 9。墙上的值是已知的，盒子的值要按方程算。
  4. 边界墙用了 k 而不是 2k → 仍是一条直线，但第一个盒子是 8.33（第 5 课练习第 3 题）。
  5. Int 和 Double 混算 → 编译报错。L / N 要写成 L / Double(N)。
  6. 数组用 let 声明 → 改内容时编译报错。
  7. 没有保险丝 → 只要哪里写错，程序就永远转下去，iPad 上的 App 会卡住。
