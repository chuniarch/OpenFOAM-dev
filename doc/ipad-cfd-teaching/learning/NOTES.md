# 教学笔记（学习者偏好 / 工作约定）

> 这些不是建议，是硬约束。违反过一次，代价是学习者当场失去抓手（见 LR-0004）。

## 讲法

1. **一次只讲一件事。** 单元叫「砖块」，按编号推进。宁可慢。
2. **每砖结尾只问一个小问题**，答对了才进下一砖。
3. **公式一律纯文本**，例如 `C_P = (a*C_P_old + Σ w*C_邻居) / (a + Σ w)`。终端渲染 LaTeX 会变乱码。
4. **举例一律用「水和墨水」**，不要用热传导。
5. **不替他写代码。** 教思考方向、设计思路、知识点、易错点。他写完发来，我只点评。
   只有他明确说「打个样」，才给完整代码，并且要顺带取好文件名（如 `Diffusion1D.ts`）。
6. **每个阶段先给验收尺子** —— 怎么用物理直觉判断结果对不对（守恒 / 对称 / 有界 / 单调 / 解析解）。
7. **问「为什么」时讲透物理本质**，不要只给公式。

## 语气与密度

8. **不要拟人化。** 他懂统计力学，也懂"微团 = 大量分子的集合"。直接说
   「大量分子的运动服从统计规律」，不要写「分子排队掷硬币」这类拟人图像。
9. **不甩没有推导过程的数字。** 任何结果都要能看到怎么来的，否则对他等于噪音。
10. **英文术语第一次出现当场翻译**，能不用就不用。人名命名的术语（Dirichlet、Laplace）要说明
    "这只是个人名，不用记"。
11. **信息密度是第一杀手。** 一条消息里出现三个以上没讲过的新概念 = 失败。参考资料 ≠ 课。
14. **每个论断都要能被跟着算一遍。** 结论前面必须有代数推导，或者带真实数字、能逐位核对的手算；
    只有"结论 + 抽象文字 + 一两个数字"就是汇报，不是教学（LR-0010）。具体做法：
    量第一次出现先定义（分子/分母各对什么求和）；两个相关的量不要来回换着叫；带维度的数把维度写进算式；
    写完拿数据逐句核对定性描述；说"前面讲过"之前先确认真的讲过。
15. **提到之前的任何内容，当场写全。** 不只是例子的条件（几个盒子、两面墙各是什么、钉死多少、墙的权重、初值、
    扫了几遍、答案），也包括做法和公式：不写「按第 5 课的办法」「前面说过」「情形甲」「墙外那缸水」这种要学习者
    回忆的话，把那个办法、那条公式、那个东西是什么当场写出来。代号是我起的，学习者没有义务记住。
    （2026-09-28 被指出一次；2026-09-29 又被质问「我都说了你还是不写，为什么」——我只把它理解成「例子的条件」，
    理解窄了。）两组数并排列出时，要当场说明它们是什么关系、为什么放在一起（LR-0013、LR-0014）。
16. **表格不能代替计算过程。** 表格里的每个数都要有算式：逐个写出，或完整写出一格并把其余各格的算式也列出来。
    「碰巧成立」的事不能写成推理（例：「残差为正，所以偏淡，和误差为负对得上」是错误推理，LR-0014）。
18. **课文里也不许用「尺子 1」「情形甲」这类编号指代例子**（2026-10-04 学习者：「什么叫作尺子 1？你就只写这一个名字」）。
    验收表里可以编号，但正文、练习、易错点里每次提到都写全条件（几个盒子、两面墙、初值、r）。
13. **练习要有难度。** 学习者反馈插页 A 的练习"比较简单"（2026-09-26）。之后每课练习至少包含：
    一道要动手算的题、一道换了数字或换了设定的迁移题；干扰项要对应一个具体的错误，并在解释里点名是哪个错。
12. **对照另一门课时，只讨论学习者已经走到的砖块。** 超前的对应关系记进 `crosswalk-stable-fluids.md`
    并标 🔒，不在对话里展开。（2026-09-24：学习者在砖块 4，我讲了砖块 10 的对应关系，被当场指出。
    与 LR-0004 是同一个失败模式：内容对，但位置错。）

## 已知的绊脚石

- **抽象向量/张量记号**（`∇·` 、下标 `∂_j`、"加零技巧"）是主要障碍。任何含张量的推导都要先在一维、
  纯乘积法则里慢慢铺垫。（来自归档会话 `context/icofoam-cavity-walkthrough.md` §1、§3.5）
- **两套记号讲同一件事而不点明**会造成困惑。例如菲克定律 `J = −D·dC/dx` 与盒子记账
  `Q = w·(C_邻居 − C_P)` —— 必须显式演示它们是同一个东西（见 LR-0005）。

## 工作约定

- 本会话产出一律写到 `openfoam-learning/main` 分支，不新建 `claude/*` 分支。
- **代码一律先用 TypeScript，不用 Swift**（2026-09-29 学习者要求：「以后的代码先不要用 swift，先用 ts」）。
  课文里的语法点、易错点、参考答案都按 TypeScript 写；原来的 Swift 参考答案留在 `code/*.swift` 存档。
  学习者在 iPad 浏览器的 TypeScript Playground 里跑，或在电脑上 `node x.ts`（Node 官方文档：22.18 起默认能直接跑 .ts）。
  这边环境有 Node 22.22 和 tsc：教学用的代码和数字直接跑 TS 核对（`node x.ts`），类型检查用
  `tsc --noEmit --strict --target es2022 --lib es2022,dom x.ts`——带 dom 是为了和 Playground 一样，
  查出最外层变量名撞上浏览器全局名（`top`、`name`、`closed`……）的错。Node 直接跑 .ts 时不支持 `enum`。
- 文档落盘后 commit + push，不留在对话里。
- `.claude/skills/` 三个分支（openfoam-learning/main、master、ipad-cfd-teaching/main）保持同步。
- 发布课文一律走 `tools/build_artifact.py`，别再手拼。它会拦下三类曾经真实出过的错：发布页里残留 `../` 引用、
  内联脚本被注释里的闭合标签截断、练习解释 `data-fb="…"` 被英文直引号截断（解释里的引号一律用「」）。
- 共享样式里有全局 `[hidden] { display: none !important; }`，组件别再依赖浏览器默认的隐藏。
- 写提交说明一律先写进文件再 `git commit -F 文件`，**不要用 `printf` 拼**：说明里只要出现 `%`（比如"削掉 9.5%"），
  printf 就会把它当格式符吃掉后面的全部内容，连署名行一起丢（2026-09-26，提交 ba727122 就是这样被截断的）。
