## 1. 教学线已走到哪（已教内容，保持连贯）

- **第一课·全景地图**：①需求→②建模→③架构→④详设→⑤实现→⑥验证；三贯穿要点（产物可追溯 / 每阶段末验证 / 阶段可迭代不可颠倒）。
- **第二课·SRS**：愿景/用户/FR/NFR/约束/范围；条目要"可单独确认、可单独验收"。
- **术语澄清**：可追溯（向前=需求→验收，向后=模块→需求）；**可验收**（跑测试判红绿灯）vs **可评审**（专家读了判对错）——需求/代码主靠可验收，模型/设计主靠可评审。
- **需求→架构 推导法（ASR 筛法）**：NFR 与约束通常比 FR 更具架构显著性；已从 SRS 推出架构决策①–⑥（Swift 引擎、资源层内嵌、联动层、Metal、GPL 策略、图形化编辑）。
- **②建模手法**：用例 = SRS 的"动词投影"（FR 给主流程、NFR/约束给异常流）；领域 = SRS 的"名词投影"（名词成概念、动词成边、再标基数）。

## 3. ③ 要做的活（开工清单）

③ 产物 = **结构视图**（分层/模块/依赖方向）+ **协作视图**（块间通信）+ **ADR**（架构决策记录：背景→选项→决策→后果）。

我们的 ③ 不是白纸作画，而是"**正规化 + 消化新输入 + 补缺口 + 评审冻结**"四步：

1. **ADR 化已定决策**：把 `architecture.md` §0 的 7 条决策逐条补成正式 ADR——背景指回 SRS 条目、**列出落选选项并写明被哪条需求否决**、写后果与缓解。
2. **拍掉 D1–D4**（来自 analysis-model §6）：detail 呈现（浮层 vs 侧栏）/ 单步粒度 / 编辑后重算策略 / 图布局算法。用 `AskUserQuestion` 交用户定。
3. **补 ③ 最大真缺口**（`architecture.md` §1.1）：引擎缺"**算子级事件广播**"接口——FR4/FR5 与思维导图"执行游标"都依赖它。当前只有粗粒度 `run(onStep:)`+`StepReport`。候选：引擎事件枚举 + `AsyncStream`。③ 必须把这个接口的形状定下来。
4. **升级资源层契约**：把 analysis-model §3 的 `graph(nodes+edges)`（思维导图）并入资源层数据格式；给 FR7 的 `ContextPack` 预留生成挂点（M5 才实现，③ 现在不能堵死）。
5. **评审 + 冻结 v0.3**：更新后的 `architecture.md` 逐段**全文贴给用户**过目、用例走查、冻结。

## 4. ③ 的验证方式（架构评审）

- **断言核实**：架构里每个事实断言（源码路径、行号、案例取值）对照真实仓库查证，延续 `architecture.md` §2.1 的评审纪律。
- **场景走查**：拿 ② 的用例 + 质量场景（性能/离线等）在架构上走一遍，每步有模块接、相关 NFR 不被违反。
